# Portfolio Builder: one evidence-backed mission spine

Status: **Curriculum architecture validated against all 38 slide/test packages and 35 narrations; Sessions 24, 27, and 32 still require narration reconciliation; implementation not started**

## 1. The single product direction

Open Portfolio Studio will have one required direction: **build and defend an implementable investment portfolio**.

The learner sees ten Portfolio Builder missions. “Modules,” Damodaran chapters, source families, and session numbers do not form competing progress systems. They are provenance and optional depth behind the missions.

Course promise:

> Build a diversified portfolio, explain why every holding is there, and leave with written rules for risk, cost, tax, rebalancing, selling, and review.

Core design:

- 10 required missions;
- approximately 6 hours 50 minutes of guided work;
- one evolving Portfolio Dossier;
- a passive implementation as the evidence-based beginner default;
- an optional, deliberately limited active sleeve only when the learner can defend an edge after costs;
- optional strategy investigations that never count against core completion;
- source provenance from every one of Damodaran’s 38 sessions.

## 2. The finished Portfolio Dossier

Completion means the learner can defend a dossier containing:

1. investor goal, horizon, liquidity needs, tax/account context, loss capacity, time available, and behavioral constraints;
2. explicit jobs for cash, bonds, equities, and any other approved exposure;
3. strategic allocation, risk budget, concentration limits, and timing boundary;
4. business and cash-flow evidence appropriate to what the portfolio owns;
5. valuation or expected-return evidence with assumptions and a decision range;
6. passive-core choice or a falsifiable active-edge claim;
7. fund or security research files with rejection criteria;
8. position sizes and stress-test results;
9. execution, contribution, cost, tax, rebalance, sell, and thesis-break rules;
10. benchmark, review cadence, and a concise defense of the complete policy.

The course is complete when this dossier is coherent and implementable. Watching all 38 source sessions is not a completion requirement.

## 4. Learner sequence and prerequisite logic

The mission order follows the investment decision, not Damodaran’s chapter order:

1. The learner defines the investor before discussing a “best” strategy.
2. Asset roles are introduced before the learner allocates capital.
3. Risk and timing limits are written before a holding is selected.
4. Business evidence is read before value is estimated.
5. Value and expected return are modeled before an active claim is accepted.
6. Passive versus active is decided before researching products or securities.
7. Holdings are selected before position sizes are finalized.
8. The assembled portfolio is stressed before operating rules are locked.
9. Execution and review rules are written before the final defense.
10. The capstone tests coherence across the complete dossier, not recall of isolated definitions.

Each mission uses introduce → model → guided practice → independent application → assessment. A mission assessment can ask only about ideas introduced and practiced in that mission or an earlier one.

## 5. Two outcomes, one standard

### Passive portfolio

- Uses diversified funds or ETFs to perform the asset roles.
- Learns company evidence and valuation through a guided look-through case so the learner understands what the funds own.
- Must defend allocation, exposure, cost, tracking, liquidity, tax treatment, and rebalancing.
- Does not need to invent a market-beating claim.

### Passive core with an active sleeve

- Keeps the same diversified core.
- Adds an active sleeve only after Mission 6 documents the claimed market error, why it should correct, the evidence, costs, capacity, position limit, and thesis-break rule.
- Opens the relevant strategy investigation before the active holding is approved.
- Can lose active-sleeve permission if later evidence or behavior violates the written rules.

Both outcomes meet the same capstone standard. Individual stock picking is never treated as the more advanced or more serious route by default.

## 6. Where the 38 sessions live

Damodaran’s sessions have three non-competing uses:

- **Mission evidence:** a short, attributed concept supports a required portfolio decision.
- **Optional investigation:** the learner can examine the full mechanics and evidence for momentum, value, growth, information trading, arbitrage, timing, or manager selection.
- **Source library:** all 38 videos, decks, and tests remain indexed for provenance and self-directed study.

Only missions appear in the primary course rail and completion percentage. Optional investigations appear as `Investigate this strategy` from the relevant mission and return to that mission. The source library has no incomplete-state badge.

## 8. Supplemental source agenda

The corpus audit found six subjects that Damodaran’s course does not teach deeply enough for the Portfolio Builder outcome:

1. strategic asset-allocation construction;
2. position sizing and concentration policy;
3. current fund and ETF due diligence;
4. rebalancing methods;
5. current tax, account, and securities-law rules;
6. investment-policy-statement and benchmark design.

Primary, current sources must be locked for these subjects before the affected mission outline is approved. Historical active/passive, fund-rating, market-timing, and product-cost claims also need current evidence rather than simple reuse.

## 9. Navigation and data requirements

The Portfolio Builder should feel like one investigation:

- the top scanner tracks the ten dossier artifacts: mandate → roles → allocation → evidence → value → architecture → holdings → sizing → operating rules → defense;
- the main progress number counts ten missions only;
- each mission is named for the portfolio decision and artifact it unlocks;
- source-session references appear in an expandable evidence panel;
- optional strategy investigations display separate time and never alter core completion;
- reduced motion replaces the scanner sweep with immediate state changes.

The data model needs explicit fields for mission identifier/order, requirement (`core`, `investigation`, or `reference`), artifact, estimated core/optional time, reused scene, and source citation. Damodaran chapter and session are source metadata, not navigation hierarchy.
